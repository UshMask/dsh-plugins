# Свой маркетплейс плагинов DSH

Личный индекс-маркетплейс для DeepSeek Harness: три готовых плагина, генератор индекса
и деплой на GitHub Pages. Друзьям достаточно один раз добавить URL индекса в DSH —
дальше плагины ставятся и обновляются как из обычного маркета.

## Что внутри

```
dsh-plugin-market/
├── market.config.json          # единственный файл, который вы правите под себя
├── packages/
│   ├── dsh-context-scale/      # шкала контекста с перетаскиваемыми порогами
│   ├── dsh-token-cost/         # плашка стоимости токенов
│   └── dsh-context-guard/      # плашка давления контекста + автосжатие
├── scripts/
│   └── generate-index.mjs      # сборка site/index.json (+ html и иконки) и валидация
├── site/                       # то, что раздаёт GitHub Pages
│   ├── index.json              # ← этот URL добавляют друзья
│   ├── index.html              # человеческая страница со списком плагинов
│   └── icons/
├── market.external.json        # плагины друзей из чужих репозиториев/npm (необязательно)
├── CONTRIBUTING.md             # как другу добавить свой плагин
└── .github/workflows/
    ├── pages.yml               # CI: проверка индекса и деплой на Pages
    └── validate.yml            # CI: валидация пул-реквестов
```

Каждый пакет — это npm-пакет с манифестом `dsh.bundle` (patch-слой профиля) и
`dsh.client` (клиентская половина для Web UI). Пакеты уже переименованы из локальных
`@local/*` в обычные имена, у них есть `engines.dsh`, README, LICENSE и иконки —
публиковать в npm не обязательно, индекс ставит их прямо из git по закреплённому коммиту.

Репозиторий уже инициализирован и закоммичен (`main`). Папка живёт внутри проекта
`Znachki`, но это отдельный git-репозиторий — при желании перенесите её куда угодно.
Чтобы случайно не закоммитить её во внешний проект, добавьте `dsh-plugin-market/`
в `.gitignore` проекта `Znachki`.

## Выкладываем за 3 шага

### 1. Создать репозиторий и включить Pages

1. Создайте на GitHub **публичный** репозиторий `UshMask/dsh-plugins` — пустой, без README.
2. Сразу включите Pages: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
   Это лучше сделать до первого пуша, чтобы первый же прогон workflow задеплоил сайт.

Репозиторий должен быть публичным: DSH ставит плагины из git, а приватный репозиторий
друзья без ваших ключей не прочитают.

### 2. Запушить

```powershell
cd C:\Users\Max\Documents\Progi\Znachki\dsh-plugin-market
git remote add origin https://github.com/UshMask/dsh-plugins.git
git push -u origin main
```

Workflow `.github/workflows/pages.yml` при каждом пуше в `main` проверяет индекс,
генерирует `site/index.json` и деплоит папку `site`. Первый деплой занимает минуту-другую;
прогресс виден во вкладке **Actions**. Если первый прогон упал на шаге deploy из-за
невключённых Pages — включите их и нажмите **Re-run all jobs**.

Если репозиторий называется иначе, поправьте `github` в `market.config.json` и поля
`repository`/`homepage`/`bugs` в трёх `package.json`, затем пересоберите индекс и закоммитьте.

### 3. Проверить, что индекс отдаётся

- человеку: <https://ushmask.github.io/dsh-plugins/>
- DSH: <https://ushmask.github.io/dsh-plugins/index.json> — должен вернуть JSON, а не 404/HTML.

Если 404 — проверьте, что workflow зелёный и Pages включён именно через GitHub Actions.

## Как подключить друзьям

1. Обновите DSH до версии из `engines.dsh` (сейчас `0.2.2-rc.1` … `0.3.0`).
2. Включите экспериментальный бандл: **Plugins → More** рядом с «Experimental plugins» →
   **Custom plugin market**.
3. **Plugins → Discover → Add index source** → вставьте
   `https://ushmask.github.io/dsh-plugins/index.json`.
4. Выберите плагин → **Install**. DSH покажет версию, git-источник и коммит — их можно
   сверить с репозиторием, — затем **Enable now**.
5. Проверка через CLI:

   ```sh
   dsh plugin --profile <profile> add <spec из карточки>
   dsh --profile <profile> --dump-config   # в выводе должен быть слой # == dsh-context-scale
   ```

Проверять наличие обновлений: **Plugins → Discover → Refresh** (маркет перечитывает индекс
и показывает новые версии; установленные из git обновляются переустановкой через карточку).

## Друзья тоже публикуют

Четыре варианта — от простого к безопасному. Инструкция для друга целиком
лежит в [CONTRIBUTING.md](CONTRIBUTING.md).

**1. Совместный доступ на запись.** GitHub → **Settings → Collaborators → Add people**,
роль **Write**. Друг клонирует репозиторий, добавляет `packages/<свой-плагин>`, запись
в `market.config.json`, запускает `node scripts/generate-index.mjs`, коммитит и пушит.
Минус: у друга полный доступ — он может менять любые плагины, индекс и CI. Годится
для одного-двух близких людей.

**2. Форк + pull request (рекомендую).** Друг форкает репозиторий, готовит пакет и
присылает PR. CI `Validate marketplace changes` проверяет манифесты, `engines.dsh`,
совпадение id клиентского бандла с именем, уникальность имён. Вы ревьюите и мержите,
после мержа Pages-workflow пересоберёт и задеплоит индекс.

Чтобы включить обязательное ревью: **Settings → Branches → Add branch protection rule**,
pattern `main`, включите **Require a pull request before merging** и
**Require status checks to pass**, выберите чек `Validate marketplace changes`.
Для полной схемы добавьте и **Require approvals: 1**.

**3. Без доступа к репозиторию.** Друг публикует плагин в своём публичном git-репозитории
или в npm и присылает имя, ссылку и пин (коммит или версию). Вы добавляете запись в
`market.external.json` и коммитите — генератор проверит источник и включит плагин в
индекс. Пример записи — в [CONTRIBUTING.md](CONTRIBUTING.md). Ограничение: точечные
обновления таких плагинов тоже вносите вы, вручную меняя коммит/версию.

**4. Друзьям вообще не нужен ваш маркет.** DSH поддерживает несколько источников:
свой репозиторий с индексом + свой Pages, а друзья просто добавляют ещё один
**Add index source**. Это самый независимый вариант, если не хочется быть единой точкой
публикации.

Что важно помнить: индекс не подписан, и любой, кто может писать в репозиторий или в
`market.external.json`, определяет, что установится у всех, кто подключил маркет.
Поэтому основной путь — PR с ревью (вариант 2), а не прямой write-доступ.

## Как выпускать новую версию

Рабочие локальные копии плагинов остаются в `.dsh-plugins/` — на них ссылается ваш
текущий профиль DSH, их не трогаем. Публикуемая версия живёт в `packages/`: переносите
правки туда.

1. Правьте код в `packages/< имя >/` — не забудьте поднять `version` в `package.json`.
2. Закоммитьте изменения (генератор откажется работать с незакоммиченным пакетом, чтобы
   индекс не ссылался на коммит, в котором нет ваших правок).
3. Пересоберите индекс: `node scripts/generate-index.mjs`.
4. Запушите: CI перегенерирует и задеплоит индекс, друзья увидят новую версию.

В индексе всегда одна актуальная версия на плагин — старая из него исчезает, но у друзей
уже установленная версия остаётся. Если нужно держать историю версий, расширьте
`plugins[].versions` в `scripts/generate-index.mjs`.

## Локальная проверка

```powershell
cd C:\Users\Max\Documents\Progi\Znachki\dsh-plugin-market
node scripts/generate-index.mjs --check   # только валидация, ничего не пишет
node scripts/generate-index.mjs           # пересобрать site/
python -m http.server 8000 --directory site
# открыть http://localhost:8000/  и  http://localhost:8000/index.json
```

Валидация ловит: отсутствие `engines.dsh`, невалидное имя/версию, отсутствующий
`dsh.bundle.patch`, битый `exports["./client"]`, дубли имён, незакоммиченные изменения и
невалидный git-пин.

Проверить содержимое пакета (что попадёт в tarball/кэш):

```powershell
npm pack --dry-run --cache .\tmp\npm-cache   (в папке пакета)
```

Проверить установку до публикации — в отдельном тестовом профиле DSH:

```powershell
dsh plugin --profile market-test add .\packages\dsh-context-scale
dsh --profile market-test --dump-config   # должен появиться слой # == dsh-context-scale
```

Профиль `market-test` создастся автоматически; после проверки его можно удалить
(каталог `C:\Users\Max\.dsh\profiles\market-test`). Внешний вид плагина проверяйте
в своём рабочем профиле, включив бандл вручную.

## Как менять имена и репозиторий

Все настройки маркета — в `market.config.json` (`github.owner`, `github.repo`,
названия, автор, категории, `enginesDsh`). После правки:

1. если меняется имя пакета — переименуйте папку в `packages/`, поле `name` в
   `package.json`, id в `client.js` (`window.__ModuleLoader__.load({ id: ... })`) и
   `name:` в `cordis.patch.yml`: **id клиентской половины обязан совпадать с именем пакета**;
2. поправьте `repository`/`homepage`/`bugs` в трёх `package.json`, если сменился GitHub;
3. `node scripts/generate-index.mjs`, коммит, пуш.

Добавление нового плагина: скопируйте папку пакета, переименуйте по шагам выше, добавьте
запись в `plugins` внутри `market.config.json` (категория и ключевые слова) и пересоберите
индекс — новые иконки и карточка появятся автоматически.

## Альтернативы раздачи

- **tarball для одного-двух друзей:** `pnpm pack` в папке пакета → отправьте `.tgz` →
  DSH → Plugins → Add plugin → путь к файлу. Ни репозитория, ни Pages не нужно.
- **npm-публикация** (имена `dsh-context-scale`, `dsh-token-cost`, `dsh-context-guard`
  свободны в npm): уберите `"private"` (сейчас его нет), выполните `npm publish --access public`
  и переключите индекс на npm: в `market.config.json` поставьте `"source": "npm"` (при
  желании — `npmPublishTimestamps`), затем пересоберите индекс. Плюс: npm-пакеты с ключевым
  словом `dsh-plugin` автоматически попадают в сторонние каталоги вроде <https://dshmp.com>.

## Troubleshooting

| Симптом | Причина и что делать |
| --- | --- |
| «Add index source» отклоняет URL | Только `http(s)`, без логина/пароля и `#`, ответ 2xx без редиректов. Проверьте, что URL заканчивается на `/index.json`. |
| Индекс открывается, но пусто | Откройте `site/index.json` и убедитесь, что `plugins` не пуст; посмотрите `Actions` — не упал ли `--check`. |
| У плагина нет подходящей версии | `engines.dsh` в пакете не пересекается с версией DSH у друга. Обновите DSH или поправьте `enginesDsh` в `market.config.json` и пересоберите индекс (только если реально протестировали). |
| Установка падает на git | Репозиторий приватный, GitHub недоступен или DSH не смог сделать `git ls-remote` (таймаут 5 с). Проверьте `git clone` вручную; как обход — tarball. |
| Плагин установлен, но интерфейса нет | Бандл выключен: включите его в **Plugins → Installed** или поставьте галочку **Enable now**; затем проверьте `dsh --profile <profile> --dump-config`. |
| Страница Pages 404 | Pages ещё не собран (подождите), включён не тот Source или workflow упал. |
| Изменения не видны в Discover | Перечитайте индекс кнопкой Refresh; маркет кэширует индекс, а браузер — страницу. |
| Оба плагина контекста показывают индикатор | `dsh-context-scale` и `dsh-context-guard` — два варианта одного индикатора, обычно ставят только один. |

## Безопасность

Маркет — это сторонний контент: DSH проверяет формат индекса, но не репутацию автора.
Ваш индекс указывает только на ваш публичный репозиторий и конкретные коммиты, поэтому
друзья могут проверить исходники. Ничего, кроме ваших плагинов, индекс не устанавливает.
